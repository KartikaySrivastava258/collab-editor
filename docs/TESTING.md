# Testing

## Suites

| Suite | Command | Size |
|---|---|---|
| Type-check | `npm run typecheck` (everything) · `npm run typecheck:core` (non-UI modules, fast) | — |
| Frontend unit / property | `npm test` | 47 tests |
| Protocol conformance | `npm run test:protocol` (TS server) · `make test-protocol-go` (Go server) | 28 tests |
| Browser E2E (Chromium) | `npx playwright test` (TS server) · `make test-e2e-go` (Go server) | 31 tests |
| Go unit / integration / fuzz | `make test-go`, `make test-race`, `make fuzz` | 50 test/fuzz functions + 2 benchmarks |
| Docker image smoke test | CI `integration` job | build, healthcheck, SIGTERM exit code |

The protocol and browser suites don't care which backend they talk to, so the exact same tests
cover the Go server and the TypeScript protocol server. CI runs them against Go.

Reference run (TypeScript server; Linux x86-64, Node 22.22.2, Chromium 141.0.7390.37 headless,
Playwright 1.56.0): 47/47 unit, 28/28 protocol, 31/31 E2E, and 62/62 with `--repeat-each=2`.
Raw output is in [`test-logs/`](test-logs/), rendered in

## Layers

**CRDT** (`frontend/src/crdt/rga.test.ts`, `backend/crdt/rga_test.go`)
- Regressions for every reproduced baseline bug, plus 10k sequential and 20k front-insert stress tests.
- Idempotency, out-of-order delivery (children before parents, deletes before inserts), causality
  validation, ID conflicts, limits.
- Unicode: emoji, combining marks, ZWJ sequences, flags, CJK, lone surrogates.
- **Property test:** 1,000 seeds × 4 replicas × 60 steps, random delivery order with duplicates.
  Every run must reach identical state, match an independent tree-traversal oracle and lose no
  insert (over 50,000 ops in total).
- **Cross-language:** 45 vectors (3,982 ops) generated by `npm run gen:vectors`. Go replays each
  in forward, reverse and 5 seeded shuffled orders and must match TS text and fingerprint byte for
  byte.
- Go fuzz target `FuzzApply` (no panics; snapshot round-trip is lossless).

**Editor** (`frontend/src/editor/editor.test.ts`): selection replacement, paste/IME-style input,
surrogate-safe boundaries (5,000 randomized cases), offset mapping, and undo/redo semantics
(merging, sealed AI insertions, own-edits-only with a concurrent collaborator).

**SyncClient** (`frontend/src/sync/SyncClient.test.ts`): deterministic tests with a fake socket
and fake clock cover backoff values and bound, `stop()` cancellation, 4001 handling, the offline
outbox, chunking, minimal resend, restoring after the server lost the room, rollback after
rejection, heartbeat and welcome timeouts, and stale AI result suppression. **One live test:**
two clients against the real TS server converge; the server is shut down (memory lost), one client
edits while it is down, the server restarts, and both clients restore the room.

**Protocol conformance** (`frontend/tests/protocol`, backend-agnostic): health and readiness;
welcome contents; presence on join/leave; replacement (4001); no echo; same-position concurrency;
delete-vs-insert; a 4-client × 600-edit randomized run compared with the server; late join with
tombstones; reconnect with offline edits; idempotent resend; `sync`; room isolation; ping;
rejection of malformed JSON, unknown types, binary frames, invalid ops, foreign authors, unknown
origins/targets, too many ops, oversized messages (1009), bad room IDs (400), bad origins (403);
AI disabled.

**Browser E2E** (`frontend/e2e`, Chromium):
- *collab*: first launch; two-client editing and presence; simultaneous typing (exact final text,
  no interleaving); room switching without leaks; join-by-link validation; recent rooms on hash
  navigation.
- *editing*: U1–U3 regressions; real IME composition via CDP with a concurrent remote edit; caret
  anchoring; undo/redo; a 10,800-character chunked paste; copy/download; a 120-step randomized edit
  sequence across two clients asserting binding ↔ CRDT consistency.
- *resilience*: an outage through a TCP proxy (honest offline state, queued edits, concurrent
  remote edits, recovery, no duplicates); confirm-before-leave with unsynced edits; refresh;
  unreachable server on first load.
- *ai*: private suggestion → insert → syncs → undoable; cancel; provider timeout; provider failure
  (fake OpenAI-compatible provider).
- *layout*: 320/375/768/1280 px with no horizontal overflow; mobile drawer focus management;
  sidebar collapse persistence; skip link; every control has an accessible name; tab order without
  traps; reduced motion; WCAG contrast of all text tokens (36 pairs, all ≥ 4.5:1, written to
  `test-results/contrast.json`).

Every E2E test fails on unexpected console errors or uncaught exceptions (the outage tests allow
only network errors).

## How the tests were checked

Passing on the first run proves little, so key suites were **mutation-checked**: a deliberate bug
was injected and the suite had to fail.

| Injected bug | Caught by |
|---|---|
| No concurrent-sibling scan in RGA | 4 CRDT tests |
| Buffered deletes dropped | 2 CRDT tests |
| Server skips author check | conformance |
| Snapshot without tombstones (original bug) | conformance |
| No presence on leave | conformance |
| Caret always jumps to end | E2E caret test (the first version **missed** this and was strengthened) |
| Local deletions ignored | E2E U1 |
| Fast-path bookkeeping drops an ID | randomized binding E2E (fails in 2.6 s) |

Running with `--repeat-each=2` once exposed a test that reused a fixed room ID, so state leaked
between repetitions (the `draftdraft` result was actually correct CRDT behaviour for two authors).
Every test now creates its own room.

## Accessibility: what is and isn't covered

Automated: keyboard reachability, accessible names, focus management of the drawer and dialog,
reduced motion, and token contrast. **Not done yet:** an axe/Lighthouse scan and testing with a real
screen reader.
